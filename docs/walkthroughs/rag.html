Flow D · FGA-filtered RAG deep-dive

Retrieval that stops at the permission line

A crafted query makes a protected document the #1 embedding hit for everyone. The retriever authorizes each candidate as the querying user against OpenFGA — so the same top hit reaches the one person entitled to it and no one else. The confused-deputy, dead. All values below are captured live.

authorize-as-userOpenFGA batch-checkno leak
01

The adversarial query — the protected doc is the top hit

Both users ask the identical question. By construction secret-roadmap (viewer: alice only) is the strongest embedding match — so retrieval alone would hand it to anyone. The four top candidates:

query: "When does the Meridian acquisition close? …"
#1secret-roadmaptop hitprotected
#2shared-budgetviewers: alice, bob
#3public-handbookpublic
#4bob-notesowner: bob
What it proves: embedding relevance is blind to permission — the protected doc surfaces first for everyone.
02

alice (a viewer) — retrieves it, and the answer names Meridian

The retriever batch-checks each candidate as user:alice. She is a viewer of secret-roadmap, so it survives the filter and grounds the answer.

rag_search as alice · candidates=4 allowed=3
#1secret-roadmapviewer ✓allowed
#2shared-budgetviewer ✓allowed
#3public-handbookpublic ✓allowed
#4bob-notesnot a viewerfiltered
// answer (grounded on the retrieved secret-roadmap)
"The Meridian acquisition closes in Q3. Timeline milestones for the acquisition
 of Meridian and the post-close integration roadmap are tracked here."
What it proves: the authorized user gets the protected content — the system isn't just hiding everything.
03

bob (not a viewer) — the SAME top hit is filtered; the answer never says Meridian

Identical query, identical #1 candidate. But user:bob is not a viewer of secret-roadmap, so the batch-check drops it post-retrieval — it never reaches the model.

rag_search as bob · candidates=4 allowed=3
#1secret-roadmapnot a viewerfiltered
#2shared-budgetviewer ✓allowed
#3public-handbookpublic ✓allowed
#4bob-notesowner ✓allowed
// answer (secret-roadmap was never in context)
"Notes from the weekly engineering sync and sprint planning. Action items for the
 backend team, the flaky test triage, and the on-call rotation for next month."
// mentions Meridian: never
What it proves: the top hit leaks to no one who lacks the tuple — a non-viewer simply has it filtered, silently and provably.

What this flow guarantees

  • ✓Every candidate is authorized as the querying user (user:{name} viewer document:{id}) — never as the agent.
  • ✓A protected doc that ranks #1 by embedding reaches only users holding the tuple.
  • ✓Filtering is post-retrieval and silent — a non-viewer's answer simply cannot cite what they can't see.

Decisions: pgvector in the existing Postgres ADR-0019; offline embedder ADR-0020; Drive-shaped ACLs ADR-0015. The attack it defeats is attack tree 4.
