Capstone · reconstruct from telemetry

A postmortem, from telemetry alone

Every flow emits OpenTelemetry — traces to Tempo, audit logs to Loki, metrics to Prometheus — stitched by a single correlation_id that is the trace id. So any past action can be reconstructed and interrogated after the fact. Here we answer one security question with nothing but the telemetry it left behind.

TempoLokiPrometheusone correlation_id

The question

When bob asked the adversarial query, did the protected roadmap reach him?

bob ran "When does the Meridian acquisition close?" — the query whose #1 embedding hit is secret-roadmap, which bob is not a viewer of. We never trust the answer text; we reconstruct what actually happened from three independent signals, all keyed to correlation_id = eec3122a4d07f0cbb27ead25ff4a32bf.

The verdict — no leak, proven from telemetry

  • ✓The trace shows the retrieval reached OpenFGA as user:bob before responding.
  • ✓Two independent audit streams agree: 4 candidates, 3 allowed — the protected doc was filtered.
  • ✓Every signal is joined by one correlation_id — the answer text was never trusted, only the record.

This is the operational payoff of the whole design: because authority decisions happen on-path and are logged with a shared correlation id, any past action — a token hand-out, an approval, a retrieval — can be audited after the fact without taking the agent's word for anything.
