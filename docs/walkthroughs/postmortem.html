A postmortem, from telemetry alone

Every flow emits OpenTelemetry — traces to Tempo, audit logs to Loki, metrics to Prometheus — stitched by the native trace id (the Tempo→Loki derived field does the join, no hand-copied correlation id). So any past action can be reconstructed and interrogated after the fact. Here we answer one security question with nothing but the telemetry it left behind.

TempoLokiPrometheusone trace id

The question

When bob asked the adversarial query, did the protected roadmap reach him?

bob ran "When does the Meridian acquisition close?" — the query whose #1 embedding hit is secret-roadmap, which bob is not a viewer of. We never trust the answer text; we reconstruct what actually happened from three independent signals, all keyed to the one trace id that the flow carried across every service.

A

Signal 1 — the trace (Tempo): what ran, and in what order

The action decomposed across four services. The retrieval reached fga.batch_check → OpenFGA before returning — the authorization is on the path, not an afterthought.

localhost:3001 — Grafana · Explore → Tempo
Reads as: query embedded → top-K found → each candidate authorized as user:bob → response. Search { .prokura.flow = "D" } to open it yourself.
B

Signal 2 — the audit logs (Loki): the decision, by two services

One click on the trace's Tempo→Loki derived field lands on its audit lines, joined by the native trace id (no correlation-id copy). The mcp and rag streams both appear and agree: 4 candidates retrieved, 3 allowed — one candidate was dropped by the filter. That dropped candidate is the protected secret-roadmap.

localhost:3001 — Grafana · Explore → Loki · trace→logs jump
Reads as: the filter ran and removed exactly one candidate for bob — recorded independently by two services, agreeing, and reachable from the trace by the native id.
C

Signal 3 — the metrics (Prometheus): the fleet was healthy around it

A snapshot of the surrounding hour — logins, token grants, protocol requests, average latency — confirms the action happened against a normally-behaving system, not a degraded one.

localhost:3001 — Grafana · Prokura — Delegation Chain
Reads as: bob's action sits well within the fleet's normal latency envelope — the provisioned dashboard, rendering live.

The verdict — no leak, proven from telemetry

  • ✓The trace shows the retrieval reached OpenFGA as user:bob before responding.
  • ✓Two independent audit streams agree: 4 candidates, 3 allowed — the protected doc was filtered.
  • ✓Every signal is joined by one trace id — the answer text was never trusted, only the record.

This is the operational payoff of the whole design: because authority decisions happen on-path and are logged under the native trace id, any past action — a token hand-out, an approval, a retrieval — can be audited after the fact without taking the agent's word for anything.
