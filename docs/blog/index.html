Agentic identity, assembled from parts you can read

Prokura is an open-source reference implementation of the plumbing that lets an AI agent act on your behalf — without ever holding your passwords or your provider tokens. It's an OSS counterpart to "Auth0 for AI agents", built from Keycloak, OpenFGA, and OpenBao. This page is the foundation and the map; each milestone has its own write-up.

Foundation shipped docker-compose reference + portfolio

The problem

An agent needs to act as you — safely

When an AI agent books a flight, reads your Drive, or opens a pull request, three questions have to be answerable at all times: is this really you the action is attributed to, which agent is acting, and exactly what is it allowed to do? Hand an agent your GitHub token and all three answers are lost.

Prokura keeps them answerable. The name is the civil-law term for a registered power of attorney — a bounded, revocable, on-the-record authority to act for someone. That is precisely the model: every action is attributable to user-via-agent, gated by explicit per-agent consent, and issued as a short-lived, narrowly-scoped credential the agent never gets to keep.

This is a reference architecture, not a product. It runs entirely on docker-compose and is explicitly non-production — the docs, the decisions, and the demo are the deliverable. Two flows get full rigor: token brokering and human approval.

The big picture

The lifecycle of a delegated request

Here is the whole story the later milestones tell, end to end. Each leg is its own milestone — a login becomes a delegated token (M1), that token is brokered into a scoped third-party token (M2), and a sensitive action pauses for a human before it runs (M3).

What M0 proved

Stand it up, then de-risk the hardest thing early

01

The compose skeleton

Keycloak, OpenFGA, OpenBao, Postgres and the observability stack come up together, wired and seeded — one docker compose up and the reference is live.

02

Login works and tokens are short

OIDC login is real, and Keycloak-issued access tokens are bound to ≤ 15 minutes — the TTL-honesty principle every later milestone inherits.

03

The CIBA spike — proving M3 before building M3

Human approval (M3) hinges on a risky bet: can Keycloak's built-in HTTP authentication channel drive out-of-band approval, so we avoid writing and maintaining a Java plugin? M0 spiked it and proved yes. That single experiment de-risked an entire future milestone — the same discipline M2 later reused for account-linking.
