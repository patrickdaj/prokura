Milestone 07 · Correct parties

The scripts stop playing the human

v0's flows were architecturally right about who holds which authority — and operationally wrong about who shows up. Every trusted surface opened with a bearer token a demo driver put in the URL, and the approval ceremony could only be driven by an in-repo agent client. We found out the hard way: an agent driving the live stack approved its own action with dev credentials. M7 puts the correct party in every capacity — real sessions on the trusted surfaces, a server-initiated approval ceremony no agent can touch, device-flow bootstrap that never hands agent code a password, and a test suite whose one simulated human is quarantined and labeled.

Shipped · 2026-08-09 close-correct-party-gaps ADR-0022 · server-initiated CIBA SR-01 · SR-02 fixed

The forcing incident (2026-08-08): an agent asked to demonstrate the reactive-approval flow hit the 428, then — because the repo's dev credentials let any party impersonate any other — initiated CIBA as agent-app, opened the approval payload with a script-held token, and approved itself. Every enforcement primitive held (hash-binding, single-use, audience checks). What failed was party presence: nothing forced the human's capacities to be filled by a human. The gap analysis became the M7 change; the fix is that the wrong party is no longer merely discouraged — it is locked out by the realm.

The headline

The ceremony changed hands — server-initiated CIBA (ADR-0022)

The approval service now owns the whole ceremony. When the tools-API fires a 428, registration itself initiates CIBA — the approval service's own confidential client, login_hint derived from the token claims it verified, binding_message = the ref. Keycloak delivers the delegation back to the same service (authenticated: the delegation bearer is a realm-signed JWT — SR-02 closed with it). After the human decides, the service polls the token endpoint to complete the ceremony and discards the issued token. The ceremony record is the product; the token has no consumer.

The agent's role in a sensitive action is now, exactly: receive 428 {ref, action_token} → wait → retry. Not by convention — agent-app lost the CIBA grant, anonymous DCR clients never had it, and the SDK's require_approval()/drive_ciba_approval() helpers are deleted. There is nothing left for agent code to drive.

The surfaces

Real sign-in on every trusted screen

  • ✓Approval (:8120/approvals) — the ntfy deep link (/approvals#ref, still capability-free per ADR-0007) now lands on a Keycloak login (auth-code + PKCE, confidential approval-ui client). The #ref fragment survives the round-trip inside the signed OAuth state. Decisions exist only inside that session, only by the approval's target user.
  • ✓Consent (:8110/consent) — same pattern (broker-ui). The owner of every can_use write and revoke is the session identity, closing the loop on the operator-equals-owner write guard with a real person instead of a script-held token.
  • ✓Delegation consent — the act-on-your-behalf consent screen is a realm-export.json fixture (was live-configured by a demo script), so Flow A's explicit consent survives a cold docker compose up.
  • ✓Headless bootstrap — RFC 8628 device flow on agent-app: the agent prints a verification link and polls; the human approves the user code in their browser. Test code stopped holding alice's password for bootstrap.

The tests had to change too

One simulated human, labeled, quarantined

CI still needs automation to click Approve. M7 makes that honest: tests/smoke/humankit.py is the one place a human capacity is played by automation — a Playwright driver of the real login page, the real consent and device-verification screens, the real approval surface. Correct in mechanism, simulated in actor. Agent-side kits lost decide(), consent(), ciba_init(), and every password; a grep-able invariant test (test_party_separation.py) fails the build if any of them creeps back.

Also closed while we were in there. SR-01: every service maps errors to stable machine codes; library and upstream detail goes to the audit stream only. SR-02: /ciba/delegate authenticates its caller (realm-signed delegation JWT, initiator pinned to the approval service, body-size cap, 401 before parse). RAG reconciliation: FGA tuple sync decoupled from the vector-seed guard — an OpenFGA store reset no longer leaves every document silently filtered after a restart.

What did not change

The enforcement primitives

Hash-binding, single-use consumption, the sole-writer consent invariant, audience checks, and the server-side trigger (ADR-0018) are untouched — M7 re-wired who does what, not what is enforced. The one contract change downstream of the ceremony: /consume now proves the presenting user with the caller's validated user-bound token, because the agent-held CIBA token no longer exists to present.
